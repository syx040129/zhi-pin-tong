# 2026-10-16 优化实现与验证

本轮无需数据库结构升级。默认 Mock 模式继续无需 AI 密钥；真实供应商调用与生产部署不在本轮验收范围。

## 实现范围

- 岗位详情：公开在线岗位；下架岗位只允许所属企业、管理员、保有对应投递记录的求职者访问。拒绝访问时不增加浏览量。浏览量使用单条原子 SQL 递增，避免整条岗位写回及计数丢失。
- 个性化推荐：支持选本人简历、城市、岗位类型、月薪区间（K）。城市和岗位类型精确匹配，薪资按区间重叠匹配。无命中时返回空态，不自动放宽用户条件。
- 推荐召回：全部符合意向的岗位按加权技能覆盖率排序，同分按岗位 id 降序；取候选池后使用原有四维公式评分。未引入未经验证的新评分权重。
- 批量计算：复用已加载的岗位技能、只查询一次简历经历、批量查询企业；真实模式一次请求生成简历与候选岗位的向量，批次失败则统一使用本地向量。
- 默认推荐仍使用最新创建简历与 6 小时缓存；指定简历或意向时即时计算，不覆盖默认推荐缓存。缓存兼容数据库秒精度。实时返回实际来源，缓存明确标注 CACHED。
- 推荐页匹配分析、默认投递简历沿用计算所用的 resumeId；本页投递成功后按钮更新为已投递。
- 投递状态：PENDING→VIEWED/INTERVIEW/REJECTED，VIEWED→INTERVIEW/REJECTED，INTERVIEW→HIRED/REJECTED；HIRED/REJECTED 为终态。同状态提交幂等，条件更新防止并发覆盖。
- 错误反馈：推荐、匹配初始化、我的投递分别展示加载失败与重试，避免显示成“没有简历/没有数据”。
- AI 参数：Chat 调用消费 max-tokens、temperature；Chat 与 Embedding HTTP 连接超时为 min(5, timeout-seconds) 秒，读取超时使用 timeout-seconds（默认 30，允许 1～120）。框架默认仅尝试一次，后续由业务降级。HTTP 超时不等于整个多模型调用流程的总截止时间。
- 前端普通请求保持 20 秒，AI 请求默认 120 秒，可通过 VITE_AI_TIMEOUT_MS 覆盖。调高后端超时时也应相应调整前端。
- 修复岗位经验要求为空时评分抛异常的问题。

## 验证命令

```powershell
# backend 目录：编译、单测、生成可执行 JAR
mvn package -q

# frontend 目录：类型检查与生产构建
npm run build
```

新增后端回归覆盖岗位权限、原子更新入口、本人简历校验、候选排序、个性化缓存隔离、批量调用、空经验字段、终态与并发冲突。真实调用通过本地 HTTP 模拟服务验证 token/temperature 参数与读取超时，不使用真实供应商或计费接口。

端到端脚本位于 `backend/scripts/verify-optimization.cjs`，依赖 Java、MySQL 客户端、Playwright 和 Chrome。先完成上述构建，在项目根目录运行：

```powershell
# mysql 不在 PATH 时设置 MYSQL_CLIENT 为 mysql.exe 的完整路径。
# Playwright 不在当前 Node 搜索路径时设置 NODE_PATH 为其 node_modules。
# MYSQL_USERNAME / MYSQL_PASSWORD 可覆盖本机开发连接参数。
node backend/scripts/verify-optimization.cjs
```

脚本只创建并清理 `careernova_verify_<时间戳>` 临时数据库；使用独立 8081 后端、5175 前端，端口被占用时提前失败。不覆盖正在运行的开发服务，不重建业务数据库。SQL 初始化文件仅在临时库执行。验证报告、服务日志和截图位于忽略跟踪的 `backend/target/optimization-*`。

## 尚未覆盖

真实模型供应商、Docker、生产部署与 Swagger 既有兼容问题未验收。岗位变更仍会失效所有默认推荐，候选召回仍读取符合意向的岗位及技能；更大数据规模下应以查询计划和压测决定进一步索引、版本缓存或检索方案。
